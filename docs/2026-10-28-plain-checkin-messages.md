# Plain Hungarian check-in messages — 2026-10-28

“Magyarázd el egyszerűbben” previously returned the original check-in questions and answers as a block of quotations. The worker deliberately replaced model paraphrases with literal quotes; that preserved provenance but removed readable explanations.

The coach now has a bounded rewrite path for check-in explanations. It extracts the latest relevant check-in's recorded categories, asks the existing shared text_chat API to arrange their verified Hungarian clauses into a short paragraph, and validates the entire returned wording against those clauses and safe connectors. Player replies use second person; coach and parent replies use the selected player's display name when available. Names and dates are attached after generation, so they are not guessed by the model. The rewrite request itself contains only the selected clauses; the original question and name are not sent in this step.

Every selected fact must appear once, with its recorded value preserved. Missing or duplicated facts, changed categories, unsupported causal links, medical/training clearance, new advice and outcome claims are rejected. In particular, “Keveset” for sleep does not become “rosszul”; a medium training amount does not become a medium-quality or unsuccessful session. Two explicit verb-spelling corrections are allowed before exact validation; there is no fuzzy semantic matching. Rejected or unavailable model output uses a readable, source-based fallback, labelled as such in the chat.

The response keeps the original source reference and a separate raw-evidence claim under “Mi alapján?”. The paragraph includes the report's actual Budapest date and past-tense attribution. It does not treat an earlier report as today's condition or propose a new training plan. Non-check-in primary content, literal-quote requests, unsupported source formats, repeat continuations and intervening user context retain their existing handling.

API 2.4.26 adds optional playerName to worker context. The shared API adapter adds a separate complete-JSON text response mode; the existing claims contract remains strict by default. Existing source retrieval and storage schemas are unchanged. Rewrite answers record the actual model and effective rewrite prompt hash. Fallbacks record habi-plain-checkin@1.

Verification includes all metric categories for both voices, date boundaries, exact source references, raw evidence separation, unrecognized/injected sources, missing facts, contradictions, changed values and unsupported conclusions. Live shared-API browser checks with synthetic records passed for player and coach, including worker claim/context/complete, named prose, collapsed evidence and the real granite4:1b-h model. The observed coach browser reply completed in 6 seconds; this is an observation, not a latency guarantee. Application tests, worker tests, lint, typecheck and production build also pass.
